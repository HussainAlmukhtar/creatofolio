# Architecture

How Creatofolio is put together, subsystem by subsystem. Paths are relative to
`app/` unless they start with `supabase/` or `docs/`. This document is dense
on purpose: it is the reference contributors (and coding agents) read before
changing a subsystem.

## Repository layout

- `app/` — the Next.js 16 / React 19 application. Run all `npm` commands here.
- `supabase/migrations/` — timestamp-prefixed SQL migrations, applied in
  filename order by the Supabase CLI (`supabase db push`). They build the whole
  database from an empty Supabase project.
- `app/src/scripts/` — `seedSupabase.ts` (demo rooms + pop-ups into an empty
  database) and two one-shot backfills under `migrations/` (`002_mint_iids.ts`,
  `003_worlds.ts`). `npm run db:seed` runs `seedSupabase.ts`, then
  `002_mint_iids.ts`, then `003_worlds.ts`.
- `app/world/` — optional per-room `<worldSlug>/rooms/<roomSlug>.json` files.
  Only used when `worlds.config.externalFilesEnabled` is true; merged on top of
  DB rows by the runtime + editor.
- `klecks/` — NOT in the repository: a checkout of
  [bitbof/klecks](https://github.com/bitbof/klecks) created by
  `app/scripts/build-klecks.mjs` on `postinstall` and as a `prebuild` hook,
  pinned to `PINNED_SHA` (0.10.1.5), patched with every
  `app/scripts/klecks-patches/*.patch` (idempotent; a patch that no longer
  applies fails the build) and built into `app/public/klecks/embed.js`. The
  iframe wrapper `app/public/klecks/index.html` is the only hand-written file
  in that directory. The patches are the ONLY place Klecks changes live (each
  hunk is marked `// [creatofolio patch]`, a historical marker name). To change one:
  edit the checkout, then
  `git add -N <new files> && git diff --binary > app/scripts/klecks-patches/0001-studio-api.patch`,
  reset the checkout and run `npm run klecks:build` to prove it applies.
- `docs/` — this file, the ops runbooks and editor UX notes.

There is no automated test suite. Type-check with `npx tsc --noEmit`, lint
with `npm run lint`, and verify behaviour in the browser. TypeScript path
alias: `@/*` → `app/src/*`.

## High-level architecture

The app has two surfaces that share the same data layer:

1. **Public game** (`/`) — Phaser 3 canvas embedded in React, navigates rooms drawn from Supabase.
2. **Admin editor** (`/admin/editor`) — Konva-based room editor (drawing via the embedded Klecks studio) that writes back to Supabase.

### Auth + access gating

- `src/proxy.ts` (Next.js 16's renamed middleware — function **must** be exported as `proxy`) refreshes Supabase auth cookies on every request via `src/lib/supabase/middleware.ts`, and admits **only the owner** to `/admin/*`: no session → `/admin/login?redirect=…`; a signed-in non-owner → `/admin/login?error=not_owner` (with a Sign out button, no redirect param so it can't loop). The maintenance/password gate is bypassed only by the owner too (a stranger with a session no longer skips it). The owner address comes from the `OWNER_EMAIL` environment variable, read in `src/lib/owner.ts` (`OWNER_EMAIL`, `isOwnerEmail`), and **must stay server-only** (no `NEXT_PUBLIC_` prefix): never import it from a `"use client"` file. Client code asks `GET /api/admin/whoami` (`{ signedIn, owner }`) instead. The login page signs a non-owner session straight back out and only follows same-site `redirect` paths. Sign-ups must also be closed on your Supabase Auth instance (hosted: Authentication settings; self-hosted GoTrue: `DISABLE_SIGNUP=true`, phone signup/autoconfirm off): the proxy is the second line of defence, RLS the third. **Two-factor (TOTP):** `/admin/security` enrols/removes authenticators and changes the password (encourage TWO devices: GoTrue TOTP has no recovery codes; recovery is server-side, `docs/ops/ACCOUNT_RECOVERY.md`). Once the owner has a VERIFIED factor, `src/lib/mfa.ts` (`mfaSatisfied`: verified factor ⇒ the access token must say `aal2`; decoded after `getUser()` validated it; fails closed) is enforced by `proxy.ts` (an owner at aal1 goes to `/admin/login?step=mfa`, not a stranger, not the owner yet) and by `getOwnerUser()` / `getOwnerState()` (`src/lib/api/owner-auth.ts`; `/api/admin/whoami` reports `{ signedIn, owner, mfaRequired }`). The login page runs the 6-digit code step after the password. The database-level twin (`owner_mfa_satisfied()` + `is_owner()` also requiring it) is `supabase/migrations/20261005000004_owner_mfa.sql` (a no-op until the owner has a verified factor; once they do, a password-only session can no longer write, so sign in with a code after enrolling; its rollback is in the file header).
- Three Supabase clients with distinct purposes:
  - `src/lib/supabase/client.ts` — browser client via `@supabase/ssr` (cookie-backed). Used by editor + game data loaders.
  - `src/lib/supabase/server.ts` — service-role client (bypasses RLS). Used **only** by owner-gated API routes: `api/editor/upload`, `api/editor/signed-url`, `api/admin/avatar-assets` and `api/admin/storage/*`.
  - `src/lib/supabase/middleware.ts` — cookie-refresh helper invoked from `proxy.ts`.
- Row-Level Security gates writes by email: `is_owner()` (`supabase/migrations/20260501000001_admin_rls.sql`, SECURITY DEFINER) compares the caller's JWT email with the single row of `public.app_owner`, a table no API role can read or write (RLS on, no policies). No row = nobody is the owner. Anon can read most editor tables (the runtime needs them); only the owner can write. `room_backups` is owner-only for both read and write. Changing the owner means updating that row (SQL editor / service role) and the `OWNER_EMAIL` environment variable together.

### Data model

Tables (base shape in `supabase/migrations/20260401000001_base_schema.sql`, the rest in the later migrations):

- `worlds` — wraps a set of rooms with a layout (`free` / `gridvania` / `linear`) + free-form `config` JSONB. Many worlds are supported: the World map (`/admin/editor/world?world=<slug>`) switches between them, creates new ones ("one room" or "a world"), and **Make live** sets `config.live` on exactly one. `loadDefaultWorld()` returns the LIVE world (`config.live`, else `main`, else first). The game registers every room (cross-world doors work as portals) but starts in the live world's `defaultRoomId` and its mini-map lists only that world's rooms (hidden entirely for a one-room world). "Reset to seed" is refused for any world but `main` (seed slugs would overwrite main's rooms).
- `rooms` — `id` (slug, primary key), `iid` (stable UUID), `world_iid` (FK), `world_x/y/w/h` for spatial layout, `config` JSONB containing the full `RoomConfig`. Schema-versioned via `config.schemaVersion`.
- `room_backups` — rolling 20-deep per-room snapshot, written on every `saveRoom`.
- `object_content` — keyed by `(room_id, object_id)`, stores the rich content (`ObjectContent` JSONB) shown in the pop-up. Two shapes: v1 (one `type` of 8) and v2 (`type: "blocks"`, `contentVersion: 2`, a `blocks` stack of shared registry blocks, or `pages`). See "Pop-ups (visitor view)" below.
- `object_templates` — reusable object presets (sprite, dimensions, hitbox, default labels; since migration `20261008000002_popup_presets` also `behaviour` = steps, walks-near, hover, kind and the source object's iid). Dropping one onto the canvas mints a fully-formed `RoomObject`.
- `drawing_scenes` — per `(room_id, target_kind, target_id)`, a `psd_path` pointing at a layered Klecks PSD in the private `drawing-scenes` bucket, so the Drawing Studio can reopen what the user last drew with layers intact. The flattened PNG is what ships to players; the PSD is the editing source.
- `sprites` — metadata for uploaded sprite images.
- `room_drafts` — ONE owner-only draft per room (`room_iid` PK → `rooms.iid`, `config`, `content` = `{ objectId: ObjectContent }` or NULL = untouched). See "Room drafts & Publish" below. Migration `20261005000001`.
- `popup_styles` / `popup_style_drafts` / `popup_style_backups` — the pop-up theme + frame library (migration `20261008000001_popup_styles`): one row per theme or frame (`config` = LIVE, `published_at` NULL = never published, `is_active` on at most one published unarchived theme via a partial unique index + CHECK). Anon reads `popup_styles`; owner-only insert/update; NO delete policy (archive-only). Drafts and history are owner-only. See "Pop-ups" below.
- `deleted_items` — the trash ("Recently deleted"): `kind` room/world/page, `label`, `payload` JSONB (row-for-row snapshots of everything needed to restore), `deleted_at`. Owner-only. Migrations `20261005000002` (table + RPCs) and `…03` (moved the 4 pre-trash orphaned page backups in as "(history only)" items). Storage files are never touched by trash/restore.

Landing versions (Shopify model): `website_page_versions` holds a page's drafts plus the live one; `website_pages.config` stays "what visitors see" and Publish copies a version into it. `website_page_versions.content` (JSONB `{ assetIid: ObjectContent }`, migration `20261004000001`) holds each version's button pop-up content so a draft's pop-ups stay off the live site; `public.publish_landing_version(slug, version_id)` swaps page row + live `website_page_content` + version stamp in one transaction. The editor feature-detects both (column missing → `42703`, function missing → `PGRST202`) and falls back to the old shared-content behaviour (with an honest toast) until the migration is applied. **Site config (`website_site_config`: nav, footer, fonts, language switch, maintenance) is live-on-save by design**: it is not versioned and not part of page drafts, so page Save/Publish never write it; it has its own explicit "Save & go live" (SiteChangesPill, Site settings, Nav Studio).

Storage buckets: `sprites`, `content-images`, `room-backgrounds`, `avatar-assets`, `content-videos`, `content-files` (PDFs + sound files for pop-up downloads/audio; bucket `allowed_mime_types` = PDF + 7 audio types, 25 MB), `site-fonts` (all public read), `room-bg-originals` (private — raw uploads kept for re-cropping), `drawing-scenes` (private — Klecks PSDs).

Supabase can be hosted or self-hosted, and files can be served straight from a bucket/CDN (e.g. Cloudflare R2) instead of the Storage API. Saved configs store absolute public Storage URLs, so `src/lib/storageUrl.ts` re-roots every `…/storage/v1/object/public/<bucket>/<path>` URL on read (in `migrateRoom`, `migrateLandingPage`, `migrateSiteConfig`, the content loaders and `getPublicUrl` call sites) at `NEXT_PUBLIC_STORAGE_PUBLIC_URL` if set, else `NEXT_PUBLIC_SUPABASE_URL`. `next.config.ts` remotePatterns and `AssetImage.canOptimizeImage()` share `storageImageHosts()`. `AssetImage` falls back to an unoptimized `<img>` if `/_next/image` fails (Next 16 refuses upstreams resolving to private IPs).

### Stable identifiers (iids) — important invariant

Rooms, objects, and entry points each have **two** identifiers:
- `id` — human slug (editable, used in URLs/dropdowns).
- `iid` — opaque UUID (never user-edited, the canonical link target).

Door cross-room references prefer `targetRoomIid` / `targetEntryPointIid` over the deprecated `targetRoomId` / `targetEntryPointId`. Slugs survive renames because doors point at iids. The dual-write window is still active, so writers set both fields and readers prefer the iid (see `resolveDoorTargetRoom()` in `src/lib/integrityCheck.ts`).

`iid` is `?` (optional) in the TypeScript types so legacy DB rows still parse; load-time coercion in `src/data/roomCoerce.ts` + the migration step `mintIidsIfMissing` in `src/data/migrations.ts` mints any missing iids on read. The one-shot `002_mint_iids.ts` script backfills DB rows.

### Schema migrations on read

`src/data/migrations.ts` is the single source of truth for the in-memory `RoomConfig` shape. `CURRENT_ROOM_SCHEMA_VERSION` is bumped whenever `ROOM_MIGRATIONS` gains an entry; loaders walk `from = raw.schemaVersion ?? 1` up to the current version and stamp the result. Writers don't need to remember to bump — `migrateRoom()` runs on read, and the stamped version persists on the next save.

When adding a new schema migration: add the function as `ROOM_MIGRATIONS[N]` (transforms version N → N+1), bump `CURRENT_ROOM_SCHEMA_VERSION`. Do **not** retrofit old data shapes into `RoomConfig` — keep the migration function loose-typed (`any`) and let the registered step normalize.

### Runtime data load — fallback chain

`src/lib/gameData.ts::loadAllRoomConfigs()` (game) and `src/lib/editorData.ts::loadAllRoomsForEditor()` (editor) layer three sources, last write wins:

1. Static seed (`src/data/staticRooms.ts`) — used **only when the DB is empty or unreachable** so something always renders. Once the `rooms` table has rows it is the source of truth (a room deleted in the World map stays deleted).
2. Supabase `rooms` table — replaces the seed when reachable.
3. (Optional) Per-room JSON files in `app/world/<worldSlug>/rooms/<slug>.json` — overrides DB **only** when the world's `externalFilesEnabled` is true. The API for this lives at `src/app/api/editor/world-file/route.ts` (hard-locked to `[a-z0-9_-]+` slugs to prevent path traversal).

Editor loaders return a `source` tag (`"supabase" | "static" | "missing"`) so the UI can warn the user when edits won't persist; the runtime intentionally falls back silently so public visitors always see the site.

### Phaser ↔ React boundary

- Phaser cannot SSR — every component that imports it must be dynamic-imported with `{ ssr: false }`. See `src/app/admin/editor/page.tsx` and `src/components/game/GameWrapper.tsx`.
- `src/components/game/EventBridge.ts` is a singleton emitter for both directions. React subscribes in `useEffect`, Phaser scenes subscribe in `create()`. Event names are constants on `EVENTS`.
- `src/components/game/PhaserGame.tsx` hydrates the room map from Supabase **before** instantiating the Phaser game and stuffs it into `game.registry.set("roomConfigs", ...)`. `BootScene` reads it back and registers one `DynamicRoomScene` per loaded room — there are **no per-slug scene classes** anymore, so adding a room is a data change, never a code change.
- `BaseRoomScene.ts` is the abstract scene that does click-to-walk, depth sorting, object zones, transitions; `DynamicRoomScene.ts` is a thin pass-through subclass. Object sprite textures are keyed by URL (Phaser's texture cache is game-wide; object ids are only unique per room).
- `systems/ObjectFx.ts` — per-object hover effects (`hoverEffect`, default "auto" = lift if clickable, scaled by `hoverIntensity` 0.25–2), hover name tag (`hoverLabel`), secret objects (`revealOnHover`), show/hide (`setHidden`, for "Show / hide" steps and `hiddenAtStart`), effect steps (`playReaction`) and Easter eggs (`easterEgg`: click / N clicks / hover → sparkle, confetti, spin, jump, wiggle, shake + optional bilingual bubble). Used by both `BaseRoomScene` and the editor's `PreviewScene`.
- **Object steps.** `RoomObject.interactions` = `{ click?: Trigger, near?: Trigger & { enabled } }`, a `Trigger` = ordered `ObjectAction[]` + `once` (never / session = sessionStorage / forever = localStorage, key `once:<roomIid>:<objectIid>:<click|near>`; the lab harness keeps them in memory). Step kinds: popup, open-popup, door (the door's OWN target fields, so the rename rewrite + door integrity rules are untouched), go-to-room, link (`confirm` = the paper "Leaving the site?" dialog), email, download, dialogue, effect, sound, toggle-object, shop (inert), wait. References are iids only. Pure helpers: `lib/objectActions.ts` (`clickTriggerOf` / `nearTriggerOf`: an object without `interactions` DERIVES its steps from the legacy `interactionType`/`externalUrl`, reproducing the old runtime exactly; `withLegacyInteraction(s)`: the DUAL-WRITE of those legacy fields, applied by the side panel and by `saveRoom`/`saveRoomDraft`, so a rollback still behaves; `stepProblem`, `describeStep`, `STEP_SPECS`, `walkTargetOf`). Room schema v6 (`migrations.ts::addInteractions`) writes the derived steps; an object that already has steps keeps them unless its legacy fields disagree (edited by older code after a rollback: that edit wins). Runtime: `systems/ActionRunner.ts` (one chain per scene, steps in order, a new chain or a room change cancels between steps, a dialogue answer's steps run next) driven by `BaseRoomScene` (click: walk to the object, then run; "walks near": measured from `walkTargetOf` against `interactionRadius`, never on spawn (zones start "inside"), never while `UI_MODAL` / a door transition / another chain is active, re-arms only past radius × 1.25). Steps needing the page go to React through `EVENTS.ACTION_UI` (`game/actionUi.ts::requestActionUi`, resolves at once when nobody listens) and `game/GameActionLayer.tsx` (pop-up, link confirm via `PopupModal`'s `children`, mailto, download; mounted by `GameWrapper` and the lab harness). Every URL goes through `safeUrl` in the editor (inline error + integrity issue) AND at runtime (refused quietly). Every step run is announced on `EVENTS.ACTION_STEP` (the lab's step log). Editor: `components/editor/interactions/InteractionsSection.tsx` in Object Properties (Kind = Object / Door / Character (data value `npc`), "When clicked…" step cards with ⋯ move/duplicate/delete and a grouped "Add a step" menu, "When the player walks near…" + radius (the canvas circle is drawn around the walk-to point), Hover with an intensity slider, "Starts hidden"). `runIntegrityCheck` flags empty/unsafe URLs, missing rooms/objects/entry points, bad emails and half-translated step text; go-to-room steps count as inbound links. Templates keep the steps too (`object_templates.behaviour`, migration `20261008000002_popup_presets`: `templateBehaviourOf` on save, `objectFieldsFromBehaviour` on drop); a drop or a duplicate re-points steps that referenced the ORIGINAL object (toggle / open-popup by iid) at the new one (`remapInteractions`; dialogue line/answer ids are fresh). Without that migration, `saveTemplate` retries without `behaviour` and the toast says the steps weren't kept.
- **Step through pop-ups.** `RoomConfig.popupNav = { enabled, order? }` (Room Properties → Pop-ups, `editor/interactions/PopupNavSection.tsx`; off by default). `popupSequence(room)` = the author's order, then every object whose click shows its own pop-up, left to right. The scene sends the visible sequence with a "popup" step (`ActionUiRequest.sequence`); `GameActionLayer` keeps the shell open and swaps content; `PopupModal`'s `nav` draws the arrows (the theme's drawn prev/next when present; a missing "next" = "prev" flipped) at the screen sides with "2 of 5" (phones: a bar above the card) and handles ←/→, mirrored in Arabic. A magazine (`PopupPages`, capture listener) turns its own pages first and lets the key through at its first/last page.
- **Dialogue box.** A "Talk (dialogue box)" step holds a `Dialogue` (`speaker`, `lines[]` of `{ en, ar }` text, optional `choices` on a line, each with its own steps). `components/game/DialogueBox.tsx` renders it at the bottom of the screen (z 80, a soft scrim; game input frozen through `GameActionLayer`'s open state): typewriter (instant under reduced motion; a click / Space / Enter finishes the line, the next one moves on; the typed count never goes backwards), answers appear once a line is typed (focus on the first, ↑/↓, Enter or click picks; picking ends the conversation and the runner runs that answer's steps before the rest of the chain), Esc closes (the chain goes on), RTL, `role="dialog"` named by the speaker, the full line announced once through `aria-live`. Theme parts: the dialogue box is nine-sliced with `PopupThemeConfig.dialogueSlice` at `panelScale` (set with the slice guides in the library), the name plate and answers keep their drawn round caps, the next mark is the drawn image; without a theme, the pop-up's paper look. `preview={{ line }}` renders a still copy (conversation editor, the theme library's Dialogue sample). Editor: `components/editor/interactions/DialogueEditor.tsx` (speaker, lines EN/AR side by side with "missing" marks, up to 4 answers per line with their own step list (no nested conversation or door step), "never shown" warning for lines after one with answers, live preview in EN/AR). Integrity: empty conversations, unworded answers, answer steps' problems, half-translated lines.
- `systems/RoomNameTag.ts` — the room's name tag (small paper tag in the site's display font, top-left; top-right with the icon after the name in Arabic). Shown per `RoomConfig.nameTag.show` (`world` default / `show` / `hide`), else the live world's `WorldSettings.roomNameTags` (Project settings; default on; passed through `GameBootData.roomNameTags` → registry `roomNameTags`). Icon none / pin / the owner's drawing or upload (`nameTag.art`, rasterised onto a canvas so SVGs work). Edited in Room Properties → Room name tag (`editor/RoomNameTagSection.tsx`, reuses `popup-styles/ArtPicker`).
- The canvas design size is fixed at **1520×960** (`ROOM_WIDTH` × `ROOM_HEIGHT` in `src/data/roomTypes.ts`). All rooms render and edit at this resolution; loaded rooms are coerced to it on hydrate.

### Editor state

`src/stores/editorStore.ts` is a Zustand store wrapped with `zundo` for undo/redo. Undo history is cleared on every `loadRoom` (it's per-room). Unsaved edits survive room switches via `dirtyRoomIds` and Save writes all of them; content edits are tracked in `dirtyContentKeys` (only those are written) and deleted/renamed objects queue `pendingContentDeletes`. Content rows are pulled per room on first open (`ensureContentLoaded`). Canvas transforms go through `transformObject` (one write = one undo step). Deleting an object keeps its content in memory (so undo restores it); Save deletes content rows whose object no longer exists. Delete from UI via `deleteObjectWithUndo` in `src/lib/editorActions.ts` (toast with Undo); announce canvas actions to screen readers with `announce()` from `src/lib/a11yAnnounce.ts` (live region rendered by `EditorWrapper`). UX polish scope + shortcut list: `docs/world-editor/UX_POLISH_SCOPE.md`. Rename object/entry-point slugs only through `renameObject` / `renameEntryPoint` (they move selection, content and drawing layers); `renameRoom` in editorData computes the door rewrites client-side (`lib/doorRewrite.ts::rewriteInboundDoors`, one rule for live AND draft configs) and calls `rename_room_atomic` (ONE transaction: stale-token check `40001`, neighbour doors, neighbours' DRAFT doors sent as extra `{ kind: "draft", id, expected_updated_at, config }` entries (only when migration `20261006000001_history_kind_trash_pointers_draft_renames` is detected, because the older function would read them as room entries), the id change, the content/drawing/sprite re-key, the draft's `config.id`, the worlds' start room); `renameLandingPage` → `rename_landing_page_atomic`. `deleteRoom` / `deleteWorld` / `deleteLandingPage` call `trash_room` / `trash_world` / `trash_landing_page` (move into `deleted_items`; the start room of the live world is refused with `P0001 start_room`). All of these feature-detect `PGRST202` and fall back to the old client-side steps (permanent deletes) when migration `20261005000002_trash_and_atomic_ops` isn't applied. `restore_deleted_item` re-inserts everything (a taken slug raises `23505 slug_taken`; restored pages come back OFFLINE; a restored room becomes its world's start room again when that world still exists and has no/missing start room: `_trash_room_rows` stores `payload.start_for_worlds`); `purge_deleted_items` is the only permanent delete. UI: `RecentlyDeletedPanel` (dashboard card, World map toolbar, landing page switcher) + an Undo action on the delete toasts; `src/lib/trashData.ts`. Big surface area (~600 lines). Saves are non-silent: write helpers in `src/lib/editorData.ts` return `{ ok, error?, code? }` (`code`: `session` | `forbidden` | `not_found` | `conflict`) and the store surfaces failures via Sonner toasts rather than flipping `isDirty=false`. `src/lib/writeGuard.ts` turns RLS outcomes into honest results: a non-owner `UPDATE`/`DELETE` "succeeds" with 0 rows and an insert/upsert fails `42501`, so every primary write selects the affected rows (`.select("id")`) and uses `writeErrorFor` / `noRowsResult`; both mark `useSessionStore` lost when the session lapsed. `useOwnerSessionWatch` (auth events + a throttled focus/visibility `getUser()` check) drives `SessionLostBanner`, mounted on the editors, dashboard and wardrobe. **Optimistic concurrency:** `updated_at` is the token. `saveRoom(config, { expectedUpdatedAt, force })`, `saveLandingVersion(…, { expectedUpdatedAt, force, content })` and `saveSiteConfig(config, expected, force)` only update when the row is unchanged, else return `code: "conflict"` (never overwrite silently). The room editor keeps `roomRevisions` (hydrate / `refreshRoomRevisions` / `reloadRoomFromDb`; outside zundo's `partialize`) and shows a Keep both / Overwrite / Cancel dialog per conflicting room (`useChoiceDialog`); landing drafts offer save-as-new-draft / load theirs / overwrite (publish aborts on conflict); site settings reload/overwrite via `SiteConflictDialog`. Any new writer of `rooms.config` must bump `updated_at`. `useTabPresence` warns when the same room/draft is open in another tab of this browser. **The `rooms.world_*` columns are the source of truth for world-map placement**: loaders overlay them onto `config`, and `saveRoom`'s update path never writes them (only an insert does), so saving a room can't snap it back to a stale position. Drafts are autosaved to IndexedDB by `useDraftAutosave` (`src/lib/useDraftAutosave.ts`) so a tab crash doesn't lose work.

**iPad hardening (admin only, `html[data-touch]`):** no rubber-band / pull-to-refresh (`overscroll-behavior: none`), no iOS callout or selection on canvases, hit boxes, Moveable controls and the studio (inputs keep selection for typing, Scribble, paste); hover-only UI is Tailwind `hover:` / `group-hover:` (v4 gates them behind `@media (hover: hover)`, so Pencil hover opens nothing) or paired with `touch:`. Edge-swipe "back" does not fire `beforeunload` in Safari: `lib/useBackSwipeGuard.ts` (room editor, landing editor, pop-up style editor) pushes ONE sentinel history entry while dirty (a COPY of the current state plus a marker: Next reloads on foreign state) and confirms before leaving; the existing `beforeunload` guards stay.

### Drawing Studio (Klecks iframe, three hosts)

`app/public/klecks/index.html` is the hand-written BRIDGE (postMessage protocol in `src/components/studio/studioProtocol.ts`); `components/studio/` is the host side: `useStudioBridge` (iframe ref, ready, `studioState`, guide-proof `requestExport`, restore offers), `useStudioFullscreen` (Fullscreen API where it exists + an edge-to-edge overlay fallback, preference in localStorage `studio:fullscreen`), `StudioModal` (shared chrome: Pencil only, Guides, brush presets, Full screen, draft status, memory warning, restore dialog; edge-to-edge by default on touch). Hosts: `LandingDrawModal` (landing elements, arcade backdrop + machine layers, nav art, pop-up theme parts via `popup-styles/ArtPicker`) and the room editor's `DrawModalInner`; both supply title, save buttons and `autosaveKey`. **GUIDE layers (name starts `GUIDE`) are never in a saved PNG:** the bridge exports through `native` (patched `getPNGExcludingLayers`) → `project` (compose from the layers' canvases) → `hide` (hide guides via Klecks, `getPNG`, restore); it reports `pngPath` + `guideStripped`, never falls back to a flattening `getPNG` while a guide may exist, and `useStudioBridge` REFUSES (toast, no upload) a PNG whose path didn't strip. The bridge only uses the patched public API (never `klecks.instance` / `.embed` / `.klApp`: those differ between Klecks versions). Dev hosts only (`localhost`): `requestExport` accepts `forcePath` (`native` / `project` / `hide` / `getPNG`) to prove each path. Pencil only: mode `on` / `off` / `auto` (auto = on once a pen touched the screen this session), `localStorage creatofolio-studio:pencil-only`. ### Layer lock (every editor that positions layers on a canvas)

Each positioned element carries an optional stored `locked?: boolean` (editor-only metadata: **no public component or game scene reads it**; no migration, no schema bump, because the loaders copy assets / objects with spreads; `resolveArcade` carries `machine.locked` explicitly). `true`/`false` = the owner chose and always wins; **absent = the default: locked for a backdrop, free for everything else.** The decision lives in ONE module, `lib/layerLock.ts` (never repeat a backdrop test): `isAssetLocked(asset, section)` (landing + Arcade scene elements; `isSectionBackdrop` = a drawn/uploaded image at the bottom of the stack covering ≥ 95 % of the section box; in the Arcade it is `isBackdropAsset` from `arcadeGuides.ts`), `isMachineLocked(arcade)` (`arcade.machine.locked`, free by default), `isRoomObjectLocked(obj)` (`RoomObject.locked`; default-locked only when an *object* covers ≥ 95 % of the room, the room's own background layers are fixed at room size and can't be dragged), `isHotspotLocked(rect)` (`NavHotspot.locked`, Nav Studio, free by default). A locked element can't be moved / resized / rotated / nudged (arrow keys, `moveAssets`, `moveObjects`, `transformObject(s)`, align / distribute all skip it; store-level guards, not just UI), is skipped by marquee, select-all and the Tab cycle, and its canvas hit area is **click-through** (landing: the hit box gets `pointer-events: none`, so a press lands on the overlay box / the unlocked element beneath and a finger scrolls; Konva: the object's Group has `listening={false}` and the Transformer never gets its node; Arcade machine: click-through in the Select tool only, the Screen / Frames tools are explicit placement tools; the explicit "Re-place" backdrop dialog and art-driven fits like Replace image still work). It stays selectable from the layers list: it then shows a thin outline + padlock badge instead of handles, the inspector shows a "Locked" note with Unlock and read-only X/Y/W/H/rotation (`LockControls.tsx` for landing/Arcade, inline in `EditorSidePanel`). Toggles: a padlock on every layers row (always visible on touch, ≥ 44 px; locked rows always show it closed), the inspector header, the floating element toolbar / long-press `ElementContextMenu` / ⋯ menus (`SelectionActions`) / the room's right-click menu, and **Ctrl/⌘+Shift+L** (landing `LandingEditorWrapper`, room `EditorWrapper`, Nav Studio `HotspotEditor`, which captures it so an open Nav Studio doesn't also toggle a page element). A toggle is one undo step through the normal store (`toggleAssetLock`, `toggleMachineLock`, `toggleObjectsLock`; feedback wrappers in `lib/landingEditorActions.ts` / `lib/editorActions.ts` announce it), marks the page / room dirty and is saved with the version draft / room draft. Site config (Nav Studio) has no undo by design, so a hotspot lock is saved with "Save & go live". A copy / paste / duplicate of an effectively-locked element gets an explicit `locked: true` (a nudged copy would stop being a backdrop). A drag that starts on a SELECTED locked element shows the once-per-session "Locked: unlock it to move" toast with an Unlock action (`showLockedHint`). The room editor's old session-only `lockedObjectIds` Set is gone; its unrelated zIndex pin (`lockLayer`) is labelled **Pin depth** in the UI. `hiddenObjectIds` is still session-only. Skipped on purpose (not stacked layers): Arcade camera frames, room background layers, world-map room nodes (live-immediate DB columns), pop-up style screen / slice editors, the crop and backdrop-place dialogs.

### Unused files

`/admin/storage` lists every Storage object nothing points at, with bucket totals. `lib/storageRefs.ts` (pure) extracts referenced `bucket/path` keys from any row (public URLs of any origin, plus the bare ones: `drawing_scenes.psd_path`, `sprites.storage_path`, `*OriginalPath`, landing `sceneId` → `drawing-scenes/landing/<id>.psd`); `lib/storageScan.ts` (server-only, takes the client as a parameter) reads ALL 20 reference tables (the 3 popup_style tables and `popup_presets` count as empty when migration `20261008000001_popup_styles` / `20261008000002_popup_presets` is missing; any other read error still aborts) (rooms, drafts, backups, content, versions, templates, trash…; **a failed read aborts the scan** rather than looking like "unused"), lists the 9 buckets recursively, and never lists files < 48 h old. `GET /api/admin/storage/unused` and `POST /api/admin/storage/delete` (max 200; re-scans server-side and refuses anything referenced/too new) are owner-only (`getOwnerUser()`). Deleting is owner-driven only: no automatic cleanup. **New table or column that stores a file reference → add the table to `REFERENCE_TABLES`** (or its files will be listed as unused).

### Public home page (SEO)

`app/page.tsx` is a SERVER component (`revalidate = 60`): it loads the published home page + site config, renders `<LandingPage initialPage={…} initialSiteConfig={…}>` (no client re-fetch; `useSiteConfig(initial)` skips its swap, so the first paint already has the real header/footer/fonts; `[slug]/page.tsx` does the same through `SubPageView`; `AnnouncementBar` reads its localStorage dismissal through `useSyncExternalStore` so server and client markup agree; unlike `previewPage` it changes nothing else). The anon client in `landingData.ts` uses its own `storageKey` so supabase-js doesn't warn about two GoTrue clients and builds `generateMetadata` via `src/lib/landingMetadata.ts` (title/description from `DrawnPage.meta`, `openGraph`/`twitter` cards with `meta.ogImage` ?? `SiteConfig.seo.defaultOgImage`; `/[slug]` shares the builder). The loaders fall back silently to the static seed, so the site never breaks. `SiteConfig.seo` ({ siteName, defaultOgImage, twitterHandle }) is carried through `migrateSiteConfig` explicitly (it rebuilds from known keys). **Instant publish:** `POST /api/admin/revalidate` (owner-only; paths `/`, `/<slug>`, `/sitemap.xml`; `layout: true` for site settings) is called best-effort (`src/lib/revalidateSite.ts`) after landing Publish / status change and site "Save & go live"; the 60 s ISR remains the safety net.

### Loading screen

`SiteConfig.loader` (`data/loaderConfig.ts`: `LoaderConfig`, `normalizeLoader` carried by `migrateSiteConfig`, absent = ON with the book preset (id `book`) (`DEFAULT_LOADER`; switching it off stores `enabled: false`); no migration, live-on-save like the rest of the site settings) drives `components/landing/loader/SiteLoader.tsx`, mounted by `LandingPage` (home; never with `previewPage`) and `SubPageView` (only when `pages: "all"`), and only from the SERVER-loaded config so it is in the first HTML. Six presets (`LOADER_PRESETS`: spin, hop, scribble "Being drawn", flipbook (plays only the drawn frames f1–f4), orbit, book (id `book`)) × four exits (fade, curtain, book = the sheet swings open on its hinge, iris = `@property --ld-hole` mask), progress line/dots/percent/none; every drawable slot (`art[slot]` = `DrawnArt`, keys main/f1–f4/o1–o3/cover) falls back to an inline ink doodle (`LoaderArt.tsx`). All motion is CSS (`siteLoader.css`, durations ÷ `--loader-speed`, sizes in container units so the editor preview scales) so it moves before hydration. An inline boot script (rendered inside the loader) runs before paint: caption language from `localStorage creatofolio-language` (`html[data-loader-lang]`), `html.site-loading` scroll lock, and `html[data-loader-skip]` for `showOn: "session"` (`sessionStorage creatofolio-loader-seen`). "Loaded" = load event + `document.fonts` + every eager `<img>` complete, polled on a 50 ms TIMER (never rAF: frames pause in occluded windows), filled no faster than `minMs` counted from navigation start, hard cap 10 s, CSS failsafe at 15 s, hidden under `<noscript>`; client-side navigations never show it (module flag + `html[data-loader-boot]`, set only by the server-rendered boot script). Leaving unlocks scroll, restarts Lenis and refreshes ScrollTrigger. The book preset opens its cover (550 ms) before the exit; in Arabic the hinge is on the right. Editor: `/admin/loading-screen` (`components/loading-screen/LoadingScreenEditor.tsx`, dashboard card): on/off, animated preset gallery, `ArtPicker` per slot (Draw over a `lib/loaderGuides.ts` GUIDE layer / Upload / placeholder), caption EN/AR, paper/colours/size/speed, progress, exit, when; preview desktop/phone, EN/AR, Loop or Play the intro onto a stand-in page; Save & go live = `siteConfigEditorStore.save()` (+ `SiteConflictDialog`). Loader art lives in `website_site_config`, already a storage-scan reference table.

### API routes

All under `src/app/api/`. The proxy does **not** cover `/api/*` — every write handler must call `getOwnerUser()` (`src/lib/api/owner-auth.ts`) and return 403 otherwise (anonymous PUT/POST → 403). The routes that use the **service-role** Supabase client (`src/lib/supabase/server.ts`), which RLS does not gate, are `editor/upload`, `editor/signed-url`, `admin/avatar-assets` and `admin/storage/*`: every handler in them is owner-only. The GETs that are not owner-gated (`editor/world-file`, `admin/whoami`, `forms/submit`, `site-access`) return nothing an anonymous visitor could not already read. Anything that runs on a public path must NOT use the service-role client.

Under `src/app/api/editor/`:

- `upload/route.ts` — multipart upload to a Storage bucket. Bucket allowlist (`sprites`, `content-images`, `room-backgrounds`, `room-bg-originals`, `drawing-scenes`, `avatar-assets`, `content-videos`, `content-files`), custom `path` rejects `..` / leading `/` / `\`, optional `folder` (`[a-z0-9_-]`, generated readable name `<time>-<rand>-<slug>.<ext>`), 25 MB cap (413), `upsert` only when a custom path is given (PSD re-saves). Type checks (415): `content-videos` takes video only (extension AND reported `video/*` type), `content-files` takes PDF + audio only (same list as the bucket allowlist in migration `20261007000001_content_files_bucket`; never HTML/SVG/executables); the stored contentType is the canonical one for the extension.
- `signed-url/route.ts` — short-lived signed URLs for private bucket access.
- `world-file/route.ts` — read/write/rename per-room JSON files under `app/world/`; POST/PATCH return 501 in production unless `ALLOW_WORLD_FILES=1` (container files are wiped on deploy) and the Project Settings toggle is disabled there. **Slug validation (`/^[a-z0-9][a-z0-9_-]*$/`) is the only thing protecting against path traversal — never relax it.**

Under `src/app/api/admin/`: `whoami` (`{ signedIn, owner, mfaRequired }`), `avatar-assets` (owner-only CRUD on the wardrobe catalogue), `revalidate` (above), `storage/unused` and `storage/delete` (both above), and `storage/sizes` (owner-only; POST `{ urls }`, max 200 → byte sizes read from Storage metadata for the room / page weight indicator; a URL outside our buckets answers `null` with no outbound request).

Public routes (never the service-role client):

- `forms/submit/route.ts` — POST is a Form block submission: body-size cap, strict validation (`lib/formSubmission.ts`), a honeypot field and a small per-IP rate limit (in-memory, per server instance), then forwarded to the server-side `FORM_WEBHOOK_URL` (optional `FORM_WEBHOOK_SECRET` sent as `X-Form-Secret`); nothing in the request can choose where the data goes. GET → `{ webhookConfigured }` for Site settings.
- `site-access/route.ts` — the unlock for the maintenance / password page (`src/lib/siteAccess.ts`): POST `{ password }` that matches `SITE_PASSWORD` sets the httpOnly site-access cookie (a hash derived from the password) for 30 days; wrong answers are rate-limited per IP. GET → `{ passwordConfigured }` for Site settings.

### Admin pages

Every `/admin` page has its own tab title and is `noindex` (`app/admin/layout.tsx` + a tiny `layout.tsx` per client route). The dashboard's landing rows show Live / Live · unpublished edits / Offline + "N drafts" (from the versions data via `versionState`), quick-link cards (Site settings → `/admin/landing-editor?open=site`, Nav Studio → `?open=nav`, honoured once on load by `LandingEditorWrapper`; Storage with totals from the scan; Security with "Two-factor: on" from `mfa.listFactors()`), and the deployed short SHA (`NEXT_PUBLIC_BUILD_SHA`, set in `next.config.ts` from `SOURCE_COMMIT`/`GIT_SHA`, hidden when empty). It also has a real maintenance toggle (confirm → `useSiteConfigEditorStore.save()`, conflicts via `SiteConflictDialog`), room Draft badges, a Security link and the Recently deleted card; the wardrobe uses the dark theme and `useDialog`.

### Internationalization

Strings carry both English and Arabic at the data layer: `name` / `nameAr`, `label` / `labelAr`, `title` / `titleAr`, etc. The active language is plumbed through React props (`language: "en" | "ar"`) and into the Phaser registry; RTL flips happen via the `dir` attribute on the welcome screen and CSS variables.
